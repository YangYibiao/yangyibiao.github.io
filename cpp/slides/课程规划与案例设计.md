# 《高级程序设计（C++）》课程规划与案例设计

## 一、课程定位

- 授课对象：南京大学计算机学院大一本科生
- 先修课程：《程序设计基础》（C 语言）
- 教学安排：**17 周 × 每周 2 学时**，共 34 学时；每份课件对应一次课
- 课程定位：从“会写 C 程序”迈向“会用 C++ 做抽象设计与工程实现”

课程不追求覆盖全部 C++ 语法，而是围绕三条主线：

1. **抽象与边界**：类、接口、继承、多态、模块
2. **生命周期与资源**：构造/析构、拷贝/移动、RAII、智能指针、异常安全
3. **复用与并发**：模板、STL、Lambda、并发与同步、声明式与事件驱动

## 三、主线案例：TaskFlow 任务管理器

### 3.1 为什么选它

- 贴近学生日常：作业、DDL、复习计划、社团任务
- 能自然承载：封装 → 生命周期 → 继承 → 多态 → STL → 资源管理 → 并发 → 事件
- 规模可控：命令行程序，不需要 GUI、数据库、网络
- 便于分层评分：功能、设计、测试、答辩

### 3.2 逐章演进

| 阶段 | 新增能力 | 涉及的 C++ 机制 | 设计问题 |
| :-- | :-- | :-- | :-- |
| 第 1 周 | 需求与 C 结构体版本 | 结构体 + 函数 | 数据与操作分离，谁能改状态？ |
| 第 2 周 | `Task` 类 | 封装、`this`、const | 不变量由谁维护？ |
| 第 3 周 | 构造/析构、`TaskList` | 初始化列表、RAII | 对象何时合法？资源何时释放？ |
| 第 4 周 | 可复制的 `Task` / `String` | 拷贝构造、赋值、三法则 | 浅拷贝为什么会双重释放？ |
| 第 5 周 | 可移动的 `Buffer` / 任务 | 移动语义、五法则 | 临时对象为什么要复制？ |
| 第 6 周 | `Task::count()`、模块化 | static、friend、`.h/.cpp` | 类级状态放哪里？接口如何稳定？ |
| 第 7 周 | `DeadlineTask` / `RecurringTask` | 继承、组合 | is-a 还是 has-a？ |
| 第 8 周 | 抽象 `Task` + `execute_all` | 虚函数、抽象类 | 新增任务类型要改哪里？ |
| 第 9 周 | `operator<` / `operator<<` / `==` | 运算符重载 | 如何让任务像值一样使用？ |
| 第 10 周 | `TaskRepository` | 文件流、`<<`/`>>` | 外部世界出错怎么办？ |
| 第 11 周 | `TaskError`、安全解析 | 异常、异常安全 | 错误在哪里表达、在哪里处理？ |
| 第 12 周 | `Repository<T>` | 类模板 | 如何复用容器逻辑？ |
| 第 13 周 | 排序、统计、调度 | STL、Lambda | 选什么容器？算法如何组合？ |
| 第 14 周 | `vector<unique_ptr<Task>>` | 所有权、智能指针 | 谁拥有任务？谁只是借用？ |
| 第 15 周 | `TaskRunner` | 线程、mutex、条件变量 | 共享队列如何安全并发？ |
| 第 16 周 | 事件日志、声明式统计 | 事件循环、Ranges | 如何解耦“何时做”和“做什么”？ |
| 第 17 周 | 完整项目 | 综合 | 如何组织、测试、讲解？ |

## 五、现代 C++ 特性的引入位置

| 标准 | 特性 | 引入章节 | 引入方式 |
| :-- | :-- | :-- | :-- |
| C++11 | `auto`、范围 `for`、`nullptr` | 第 1–2 周 | 从第一段代码开始使用 |
| C++11 | 移动语义、右值引用 | 第 5 周 | 先讲拷贝代价，再引入移动 |
| C++11 | `unique_ptr` / `shared_ptr` | 第 14 周 | 先讲内存错误，再讲所有权 |
| C++11 | Lambda | 第 13 周 | 从函数对象过渡到 Lambda |
| C++11 | `override` / `final` | 第 8 周 | 讲动态绑定时强调编译期检查 |
| C++11 | `std::thread` / `mutex` | 第 15 周 | 先演示数据竞争，再引入同步 |
| C++11 | 可变参数模板 | 第 12 周 | 作为模板的进阶用法 |
| C++14 | `make_unique`、泛型 Lambda | 第 13–14 周 | 在示例中直接使用 |
| C++17 | 结构化绑定、`optional`、`filesystem` | 第 10、11、17 周 | 在 I/O 与项目工具中使用 |
| C++17 | 折叠表达式、`scoped_lock` | 第 12、15 周 | 简化参数包与多锁 |
| C++17 | 并行算法 | 第 15 周 | 展示“一行代码并行” |
| C++20 | Ranges | 第 13、16 周 | 从 STL 算法过渡到管道 |
| C++20 | Concepts | 第 12 周 | 说明模板约束的演进 |
| C++20 | `<=>` | 第 9 周 | 作为比较运算符的现代写法 |
| C++20/23 | `span`、`format`、协程 | 第 17 周（延伸） | 只做地图式介绍，不展开 |

原则：**不为了新颖而堆特性**。每个特性都先回答“旧写法哪里痛、新写法解决什么、代价是什么”。

## 六、教学节奏建议

每份课件按 2 学时设计，建议节奏：

| 时间段 | 内容 |
| :-- | :-- |
| 0–10 min | 回顾与问题引入（上一章遗留问题 / 本章动机） |
| 10–35 min | 核心概念与原理（图示 + 对比） |
| 35–65 min | 代码分析（执行过程、对象状态、常见错误） |
| 65–85 min | 课堂任务（学生动手 / 现场编码） |
| 85–100 min | 小结、小测、答疑 |

代码页不要逐行念；重点讲“为什么这样写、如果写错会怎样、运行时发生了什么”。

## 七、考核建议（可按课程网站调整）

- 平时作业与课堂任务：20%
- 上机考核（OJ）：20%
- 课程项目：30%
- 期末笔试：30%

项目评分维度：功能完整性、设计与抽象、资源与安全、测试与调试、答辩与文档。具体比例以课程网站发布为准。

## 八、边界与取舍

本课程**不**覆盖：

- GUI 框架（Qt/MFC）的完整开发
- 大型 CMake 工程与持续集成
- C++ 模板元编程的高级技巧
- 协程、模块（Modules）的深入机制
- 无锁并发与内存模型的形式化细节

这些内容作为延伸阅读或后续课程，不在 34 学时内强行展开。
