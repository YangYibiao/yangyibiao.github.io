第一个 C++ 程序：从 printf 到 iostream

C 风格

#include <stdio.h>

int main(void) {
    int age = 19;
    printf("age = %d\n", age);
    return 0;
}

格式串与参数类型分离，类型不匹配时编译器无法检查。

C++ 风格 C++98

#include <iostream>

int main() {
    int age = 19;
    std::cout << "age = " << age << '\n';
    return 0;
}

<< 根据实参类型选择输出方式，类型安全、可扩展。

关键差异

std::cout 是对象，<< 是被重载的运算符。I/O 在 C++ 中以对象和运算符的形式提供，这正是“用类型系统表达意图”的第一个例子。

思考

为什么 C++ 不直接沿用 printf？如何输出一个自定义的 Task 对象？

C++ 不只是“带类的 C”
四个核心能力

  • 抽象：只暴露“做什么”

  • 封装：隐藏“怎么做”，保护数据

  • 继承：复用已有类型，建立 is-a 关系

  • 多态：同一接口，不同实现

两类工程能力

  • 泛型：一套代码适配多种类型

  • 资源管理：对象生命周期与资源绑定

  • 异常安全：出错时也不泄漏

  • 并发：把任务交给多个线程

辅助例子：用 C 的结构体与函数管理任务

先用一个小的 Task 记录讲“数据与操作分离”；MiniBuild 的 Target 会把同样的思想用在构建目标上。

C 风格 · 数据与操作分离task.c
#include <stdio.h>
#include <string.h>

struct Task {
    int id;
    char title[32];
    int priority;
    int done;
};

void task_add(struct Task tasks[], int *n, int id,
              const char *title, int priority) {
    tasks[*n].id = id;
    strncpy(tasks[*n].title, title, 31);
    tasks[*n].title[31] = '\0';
    tasks[*n].priority = priority;
    tasks[*n].done = 0;
    (*n)++;
}

void task_complete(struct Task *t) { t->done = 1; }

void task_print(const struct Task *t) {
    printf("[%d] %s (p=%d) %s\n",
           t->id, t->title, t->priority,
           t->done ? "done" : "todo");
}
问题暴露：谁都可以改，谁都不负责

调用方可以随意破坏不变量

struct Task t;
t.id = 1;
strcpy(t.title, "写作业");
t.priority = 2;
t.done = 0;

/* 忘记初始化？ */
struct Task u;
task_print(&u);      /* 未定义行为 */

/* 误操作？ */
t.id = -1;
t.priority = 999;
t.done = 7;          /* 语义上只应是 0/1 */
四个具体问题
  1. 表示暴露：字段可被任意读写
  2. 不变量失守：id > 0、priority ∈ [1,5] 无人保证
  3. 操作分散：新增一种任务要改多处
  4. 复用困难：换一种存储结构，所有调用方都要改
本质

数据与操作分离，导致“数据的所有者”缺位。程序规模越大，维护者越难知道哪些代码有资格修改这个数据。

过程抽象：先给操作一个名字

用函数封装“怎么做”

void task_add(struct Task tasks[], int *n, ...);
void task_complete(struct Task *t);
void task_print(const struct Task *t);
int  task_count_done(const struct Task tasks[], int n);

调用方只需要知道函数名、参数、返回值，不需要知道内部如何实现。

struct Task tasks[100];
int n = 0;
task_add(tasks, &n, 1, "写作业", 2);
task_complete(&tasks[0]);
task_print(&tasks[0]);
过程抽象解决了什么

  • 操作有了名字，意图更清晰

  • 实现可以修改，调用方不变

  • 消除了重复代码

还没有解决什么

  • 数据仍然是公开的：tasks[0].id = -1 仍合法

  • 数据与操作仍是两套东西，无法保证添加时一定走 task_add

追问

如果数据表示从数组换成链表，task_add 的签名还能保持不变吗？调用方需要知道 struct Task 的内部布局吗？

数据抽象：只描述“能做什么”

栈的抽象视图

  • push(x)：把 x 放到栈顶

  • pop()：取出栈顶元素

  • empty()：栈是否为空

满足：push(a); ...; pop() == a（后进先出）

使用者不需要知道：

  • 用数组还是链表

  • 容量多大

  • 栈顶指针叫什么

数据抽象的核心

把“数据表示”和“可实施的操作”分开描述：

  • 对外：操作的名字与语义

  • 对内：数据如何存储、算法如何实现

数据抽象是看问题的角度；封装是落实这个角度的机制。

使用者只看见“栈能做什么”，看不见“栈是怎么做的”。

封装的第一次尝试：struct + 函数仍然不够

数组版

struct Stack {
    int top;
    int buffer[100];
};

void push(struct Stack *s, int x);
int  pop(struct Stack *s);
struct Stack s;
s.top = -1;
push(&s, 12);
s.top--;        /* 误操作，编译器不报错 */

链表版

struct Stack {
    struct Node *top;
};

void push(struct Stack *s, int x);
int  pop(struct Stack *s);
struct Stack s;
s.top = NULL;
push(&s, 12);
s.top = NULL;   /* 直接清空，泄漏所有结点 */
问题

两种实现都把 top 暴露在结构体外。函数封装了操作，却没有封装数据；使用者仍能绕过函数直接改状态。

用类把数据和操作装在一起 
class Stack {
public:
    Stack() = default;

    void push(int x) {
        if (top_ == kCapacity) return;   // 简化：满则忽略
        data_[top_++] = x;
    }

    int pop() {
        if (top_ == 0) return -1;        // 简化：空返回 -1
        return data_[--top_];
    }

    bool empty() const { return top_ == 0; }

private:
    static constexpr int kCapacity = 100;
    int data_[kCapacity]{};
    int top_ = 0;
};

使用者只能通过接口操作

Stack s;
s.push(12);
s.push(34);
int x = s.pop();     // 34
bool e = s.empty();  // false

// s.top_ = -1;      // 编译错误
// s.data_[0] = 9;   // 编译错误
封装

public 构成接口，private 构成实现。编译器强制调用方走接口，不变量才有机会被守住。

封装的价值：换实现，调用方不变

数组实现

class Stack {
public:
    void push(int x);
    int pop();
    bool empty() const;
private:
    int data_[100]{};
    int top_ = 0;
};
Stack s;
s.push(1);
s.push(2);
int x = s.pop();

链表实现

class Stack {
public:
    void push(int x);
    int pop();
    bool empty() const;
private:
    struct Node { int value; Node* next; };
    Node* top_ = nullptr;
};
Stack s;
s.push(1);
s.push(2);
int x = s.pop();
结果

数据表示完全改变，调用方一行都不用改。这就是封装带来的可维护性与可替换性。

代价：多了一层间接；接口设计不好时，反而会限制实现。封装不是“把所有东西都藏起来”，而是“只暴露稳定的部分”。

类与对象：静态的规则，动态的实体

类（class）

  • 属于类型范畴

  • 存在于编译时刻

  • 描述对象有哪些数据、能做什么

  • 是创建对象的“模具”

class Task {
    // 数据成员 + 成员函数
};

对象（object）

  • 属于值范畴

  • 存在于运行时刻

  • 拥有独立的状态

  • 通过类来创建

Task t1(1, "写作业", 2);
Task t2(2, "复习", 3);
// t1 与 t2 是两块独立的内存
两个 Task 对象（示意）
t1id=1   title="写作业"   priority=2   done=false
t2id=2   title="复习"     priority=3   done=false

类只有一份定义；对象可以有很多个，各自持有自己的数据。

对象 = 状态 + 行为 + 标识
Task
- id_ : int
- title_ : string
- priority_ : int
- done_ : bool
+ complete() : void
+ print() const : void
+ is_done() const : bool
对象 t1
id_ = 1
title_ = "写作业"
priority_ = 2
done_ = false
行为由类共享
对象 t2
id_ = 2
title_ = "复习"
priority_ = 3
done_ = true
行为由类共享

状态：每个对象各自的数据（id_、done_ ...）

行为：类中定义的成员函数（complete()、print() ...）

标识：每个对象有独立地址，可被指针/引用区分

消息传递：t.complete() 到底发生了什么？

表面写法

Task t(1, "写作业", 2);
t.complete();     // 向对象 t 发送消息
t.print();

概念模型

  • 对象是接收消息的实体

  • 消息是“调用哪个成员函数 + 实参”

  • 对象用自己的状态响应该消息

编译器的视角（简化）

成员函数只有一份代码，被所有对象共享。为了知道“操作的是哪个对象”，编译器会隐式传入对象地址：

// 你写的
t.complete();

// 概念上等价于
Task::complete(&t);

这个隐式参数就是 this 指针，下一章会详细展开。

重要

面向对象程序的执行，可以看作一系列对象间的消息传递：一个对象处理消息时，又向其他对象发送消息。

面向对象四大特征
1. 抽象

只描述对象“做什么”，隐藏“怎么做”。

Stack 只暴露 push/pop，不暴露数组或链表。

2. 封装

把数据和操作装在一起，并限制访问。

private 保护不变量，public 提供接口。

3. 继承

在已有类的基础上定义新类，复用共同特征。

DeadlineTask 是一种 Task。

4. 多态

同一消息发送给不同对象，得到不同响应。

t->run() 可能执行普通任务或周期任务。

抽象是看问题的方式，封装是落实抽象的机制，继承是复用与分类的手段，多态是统一接口下允许差异。

继承一瞥：is-a 关系 
class Task {
public:
    void complete() { done_ = true; }
    bool is_done() const { return done_; }
protected:
    std::string title_;
    bool done_ = false;
};

class DeadlineTask : public Task {
public:
    void set_deadline(Date d) { deadline_ = d; }
private:
    Date deadline_;
};
语义

DeadlineTask 是一种 Task：

  • 拥有 Task 的全部成员

  • 可以增加新的成员

  • 可以重定义基类的行为

DeadlineTask d;
d.complete();       // 继承自 Task
d.set_deadline(...); // 自己新增
注意

继承表达的是 is-a。不是“有”的关系，也不是“为了复用代码”就可以继承。

多态一瞥：同一消息，不同响应 
class Task {
public:
    virtual void run() {
        std::cout << "执行普通任务\n";
    }
    virtual ~Task() = default;
};

class RecurringTask : public Task {
public:
    void run() override {
        std::cout << "执行周期任务\n";
    }
};
void execute(Task& t) {
    t.run();          // 调用哪个版本？
}

Task a;
RecurringTask b;
execute(a);           // 执行普通任务
execute(b);           // 执行周期任务
关键点

  • execute 只依赖基类接口 Task

  • 运行时根据对象的动态类型选择 run

  • 新增任务类型时，execute 不需要修改

这就是多态

高层代码面向接口编程，低层代码可以不断扩展。具体机制（虚函数、虚表）将在后面章节展开。

过程式 vs 面向对象：模块边界
过程式：按功能划分

数据公开，多个功能都可直接改；模块边界模糊。

面向对象：按对象划分

每个对象守护自己的数据，通过接口协作；模块边界清晰。

面向对象不是“把函数塞进类里”，而是让数据的所有者承担维护不变量的责任。

面向对象的收益与代价

收益

  • 抽象控制复杂度：面对接口，而非细节

  • 封装保护不变量：错误尽早暴露

  • 模块边界清晰：按类分工协作

  • 复用与扩展：继承、组合、多态

  • 更贴近问题空间：对象对应业务概念

代价

  • 设计与抽象需要经验，过度设计有害

  • 运行时的间接调用有开销（通常可接受）

  • 类比函数多：头文件、构造、析构、拷贝……

  • 继承层次过深会难以理解

  • “为了复用而继承”会制造错误抽象

判断标准

一种设计是否更好，最终看它是否提升开发效率与软件质量：可理解、可修改、可测试、可复用。

讨论

“把所有成员都设为 public，调用更方便”——这句话忽略了什么？什么时候可以适度开放？

三条贯穿课程的设计原则
单一职责

一个类只负责一件事。

Target 表示构建目标，Graph 管理依赖关系，TargetRepository 负责持久化，不要把三者塞进一个类。

开闭原则

对扩展开放，对修改关闭。

新增任务类型时，尽量新增类，而不是修改 execute 中的 switch。

组合优于继承

能用“有”表达的关系，不要用“是”表达。

Scheduler 有一个 Graph，不必继承 Graph。

这些原则会在继承、多态、模板、项目章节反复出现；现在只需建立印象，不要求背定义。

Task* t = new Task(...);

任务 1 参考实现 
#include <iostream>
#include <string>
#include <utility>

class Task {
public:
    Task(int id, std::string title, int priority)
        : id_(id), title_(std::move(title)),
          priority_(priority) {}

    void complete() { done_ = true; }
    bool is_done() const { return done_; }

    void print() const {
        std::cout << "[" << id_ << "] " << title_
                  << " (p=" << priority_ << ") "
                  << (done_ ? "done" : "todo") << "\n";
    }

private:
    int id_;
    std::string title_;
    int priority_;
    bool done_ = false;
};

int main() {
    Task t1(1, "写作业", 2);
    Task t2(2, "复习", 3);
    t1.complete();
    t1.print();
    t2.print();
}

要点

  • private 数据 + public 接口，外部无法直接破坏状态

  • 构造函数建立对象的不变量：创建完成即处于合法状态

  • std::string 自己管理内存，不需要 strncpy / '\0'

  • print() const 承诺不修改对象，常量对象也能调用

  • std::move 把临时字符串的资源“搬”进成员，避免一次拷贝

运行结果

[1] 写作业 (p=2) done

[2] 复习 (p=3) todo

小结：三个词，一条主线
抽象

只描述“做什么”，隐藏“怎么做”。接口稳定，实现可替换。

封装

数据和操作装在一起，用访问控制守住不变量。

对象

运行时独立的状态实体，通过消息与其它对象协作。

面向对象不是“把代码写进 class”，而是让每个对象守护自己的不变量，并通过稳定的接口协作。
