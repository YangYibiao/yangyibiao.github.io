本讲目标

能够把一个“数据 + 操作”的需求写成边界清晰的类，并解释对象创建、成员访问和 this 的来龙去脉。

一个类由什么构成？ 
class Target {
public:
    // 成员函数：对象能做什么
    void build();
    bool is_built() const;
    void print() const;

private:
    // 数据成员：对象有哪些状态
    int id_;
    std::string name_;
    int priority_;
    bool built_ = false;
};
三部分
  1. 数据成员：每个对象各自一份
  2. 成员函数：描述行为，所有对象共享代码
  3. 访问控制：决定谁能看见、谁能使用
顺序无关

数据成员可以写在成员函数后面；类内的名字在整个类定义中都可见。

类定义末尾的分号不能省：};。这是初学者最常见的编译错误之一。

成员函数：类内定义与类外定义

类内定义（默认建议内联）

class Target {
public:
    bool is_built() const {
        return built_;
    }
private:
    bool built_ = false;
};

适合：短小、频繁调用、实现稳定的函数。

类外定义（声明与实现分离）

class Target {
public:
    bool is_built() const;   // 声明
private:
    bool built_ = false;
};

bool Target::is_built() const {  // 定义
    return built_;
}

Target:: 限定表明它是 Target 的成员，不是全局函数。

选择

接口放类内，实现放类外，可以让头文件更稳定、编译依赖更小。是否内联由编译器决定，inline 只是建议。

访问控制：谁能看见，谁能使用
访问控制 本类成员函数 派生类 类外代码 典型用途
public ✓ ✓ ✓ 对外接口
protected ✓ ✓ ✗ 供派生类使用
private ✓ ✗ ✗ 实现细节、数据 
class Target {
public:
    void build();          // 任何人可调用
protected:
    void log_change();        // 派生类可用
private:
    int id_;                  // 仅本类可用
    std::string name_;
};
默认访问控制

  • class 的默认是 private

  • struct 的默认是 public

  • 可以多次出现 public: / private:

  • 访问控制只影响名字的使用，不影响对象布局

常见误解

private 不是“对象里看不见”，而是“编译器禁止在类外通过名字访问”。对象内存中仍然有这些成员。

接口设计：什么该公开，什么该隐藏

应该公开

  • 构造对象所需的操作

  • 业务语义明确的动作：build()、rename()

  • 查询状态且不修改对象的函数：is_built() const

  • 稳定的、调用方真正需要的接口

应该隐藏

  • 数据成员的表示方式

  • 维护不变量所需的辅助函数

  • 可能变化的具体算法

  • 调用方不需要知道的缓存、索引、句柄

接口是承诺，数据是自由。接口越稳定，实现越自由。

判断

Target 的 id_ 应不应该提供 set_id(int)？如果目标编号在创建后不应改变，这个 setter 会带来什么风险？

对象的三种创建方式

1. 栈对象（自动对象）

Target t(1, "main.o", 2);
t.build();
// 离开作用域自动销毁

2. 对象数组

Target tasks[3] = {
    Target(1, "A", 1),
    Target(2, "B", 2),
    Target(3, "C", 3)
};

3. 动态对象（堆对象）

Target* p = new Target(1, "main.o", 2);
p->build();
delete p;          // 必须配对

动态对象数组：

Target* q = new Target[3];  // 需要默认构造函数
// ...
delete[] q;             // 不能写成 delete q
配对规则 new ↔ delete，new[] ↔ delete[]。混用是未定义行为，可能只调用部分析构函数。
栈对象与堆对象：生命周期不同 
void demo() {
    Target stack_target(1, "栈对象", 2);
    Target* heap_target = new Target(2, "堆对象", 3);

    stack_target.build();
    heap_target->build();

    // 函数结束：
    // stack_target 自动销毁
    // heap_target 仍然存在，但指针丢失 -> 泄漏
}
栈
stack_target 生存
堆
heap_target 指向的对象
指针
heap_target 变量

栈对象随作用域结束自动销毁；堆对象只随 delete 销毁。

核心区别

“对象在哪里”决定“谁负责销毁”。栈对象由作用域负责，堆对象由程序员负责——这也是后面 RAII 与智能指针要解决的问题。

对象指针与成员访问 
Target t(1, "main.o", 2);
Target* p = &t;

p->build();      // 通过指针调用
(*p).print();       // 等价写法

Target& r = t;        // 引用是对象的别名
r.build();       // 像对象一样使用
三种访问形式

  • t.member：对象直接访问

  • p->member：指针访问，等价于 (*p).member

  • r.member：引用访问，r 就是对象本身

选择

需要“可空、可改指向”用指针；需要“必不为空、像对象一样用”用引用；不需要间接时直接用对象。

思考

Target* p = new Target(...); p->print(); 中，print() 怎么知道操作的是 p 指向的对象，而不是别的对象？

this 指针：成员函数的隐藏参数

你写的代码

class Target {
public:
    void set_priority(int p) {
        priority_ = p;
    }
private:
    int priority_ = 0;
};

Target a, b;
a.set_priority(1);
b.set_priority(2);

编译器看到的世界（简化）

void Target::set_priority(Target* const this, int p) {
    this->priority_ = p;
}

Target::set_priority(&a, 1);
Target::set_priority(&b, 2);
要点

  • 每个非静态成员函数都有一个隐藏的 this

  • this 的类型是 Target* const（指针本身不可改指向）

  • this 指向“当前被调用的那个对象”

  • 静态成员函数没有 this

理解

成员函数只有一份代码，this 让同一份代码能操作不同对象的数据。

this 的用途（一）：区分名字与返回自身

1. 区分同名参数与成员

class Target {
public:
    Target(int id, std::string name)
        : id_(id), name_(std::move(name)) {}

    void rename(const std::string& name) {
        this->name_ = name;
    }
private:
    int id_;
    std::string name_;
};

2. 返回对象自身，支持链式调用

class Counter {
public:
    Counter& add(int n) {
        value_ += n;
        return *this;
    }
    Counter& sub(int n) {
        value_ -= n;
        return *this;
    }
private:
    int value_ = 0;
};

Counter c;
c.add(5).sub(2).add(10);
this 的用途（二）：把自身传出去 
void log_target(const Target* t);

void Target::report() const {
    log_target(this);   // 把“我自己”传出去
}
使用场景

  • 需要把当前对象注册到观察者列表

  • 需要把自身传给回调函数

  • 需要在成员函数中与另一个同类对象比较地址

注意 const

在 const 成员函数中，this 的类型是 const Target*，不能通过它修改成员；把 this 传给接收 Target* 的函数会编译失败。

常量成员函数：承诺不修改对象 
class Target {
public:
    bool is_built() const { return built_; }
    int priority() const { return priority_; }

    void build() { built_ = true; }  // 非 const
private:
    int priority_ = 0;
    bool built_ = false;
};
void print(const Target& t) {
    t.is_built();        // OK
    t.build();       // 编译错误
}
规则

  • const 写在参数表后面：bool f() const;

  • 常量对象只能调用常量成员函数

  • 常量成员函数内不能修改非 mutable 数据成员

  • 常量引用参数是“只读借用”，不拷贝对象

设计习惯

不修改对象的成员函数一律加 const。否则常量对象、常量引用都无法调用它。

常量成员函数的重载

同一个函数名可以有两个版本，按对象的常量性选择：

class TargetList {
public:
    Target& at(int i) {          // 非 const
        return targets_[i];
    }

    const Target& at(int i) const { // const
        return targets_[i];
    }
private:
    std::vector<Target> targets_;
};
TargetList list;
list.at(0).build();        // 调用非 const 版本

const TargetList& clist = list;
clist.at(0).build();       // 错误：返回 const Target&
为什么需要两个版本

  • 非 const 对象：允许通过 at 修改元素

  • const 对象：只允许读，返回 const 引用

  • 只提供一个版本会损失能力或破坏常量性

mutable 用于“逻辑上不改变对象状态”的缓存、计数等成员；初学阶段尽量少用。
mutable：逻辑常量性 
class Target {
public:
    bool is_built() const {
        ++query_count_;       // 允许：mutable
        return built_;
    }
    int query_count() const { return query_count_; }
private:
    bool built_ = false;
    mutable int query_count_ = 0;
};
语义

  • 对象对外表现为“没有改变”

  • 内部允许修改缓存、计数器、互斥量等

  • 不是为了绕过 const，而是表达“逻辑常量”

警告

把业务字段声明为 mutable 来绕过 const 检查，会破坏接口承诺。先用设计解决问题，再考虑 mutable。

成员对象：一个对象包含另一个对象 
class FileStamp {
public:
    explicit FileStamp(long mtime) : mtime_(mtime) {}
    long mtime() const { return mtime_; }
private:
    long mtime_;
};

class FileTarget {
public:
    FileTarget(int id, const std::string& name, FileStamp stamp)
        : id_(id), name_(name), stamp_(stamp) {}
private:
    int id_;
    std::string name_;
    FileStamp stamp_;        // 成员对象
};
构造与析构

  • 创建 FileTarget 时，先构造成员对象 stamp_，再执行自身构造函数体

  • 销毁时顺序相反：先执行自身析构函数体，再析构成员对象

  • 成员对象的构造顺序按声明顺序，与初始化列表书写顺序无关

这是“组合” FileTarget 有一个 FileStamp，不是“是一种” FileStamp。这是组合关系，不是继承。
对象作为参数与返回值
形式 写法 是否拷贝 能否修改实参 适用场景
传值 void f(Target t) 是 否（改的是副本） 小对象、需要独立副本
传引用 void f(Target& t) 否 是 需要修改调用方对象
传常量引用 void f(const Target& t) 否 否 只读、大对象
传指针 void f(Target* t) 否 可 可空、需要改指向 
void build_all(std::vector<Target>& tasks) {
    for (Target& t : tasks) {
        t.build();          // 修改原对象
    }
}
void print_all(const std::vector<Target>& tasks) {
    for (const Target& t : tasks) {
        t.print();             // 只读，不拷贝
    }
}
默认选择

只读参数用 const T&；需要修改用 T&；确实需要副本或对象很小才传值。

类的作用域与名字查找 
class A {
public:
    void f() {
        g();          // OK：g 在类作用域中，后声明也可用
        x_ = 1;
    }
    void g() { }
private:
    int x_ = 0;
};

void h() {
    A a;
    a.f();            // OK
    a.g();            // OK
    // a.x_ = 1;      // 错误：private
}
三条规则
  1. 类内声明的名字在整个类作用域内可见
  2. 类外访问成员必须通过对象、指针或引用
  3. 派生类可以隐藏基类同名成员（继承章节展开）

成员函数体虽然写在类外，仍然属于类的作用域，可以直接访问私有成员。

从类定义到多文件：先看一个最小拆分

target.h

#pragma once
#include <string>

class Target {
public:
    Target(int id, std::string name, int priority);
    void build();
    void print() const;
private:
    int id_;
    std::string name_;
    int priority_;
    bool built_ = false;

target.cpp

#include "target.h"
#include <iostream>
#include <utility>

Target::Target(int id, std::string name, int priority)
    : id_(id), name_(std::move(name)),
      priority_(priority) {}

void Target::build() { built_ = true; }

void Target::print() const {
    std::cout << "[" << id_ << "] " << name_ << " "
              << (built_ ? "built" : "todo") << "\n";

说明

头文件放声明，源文件放定义；#pragma once 防止重复包含。模块化、前置声明、编译链接的细节在第 6 单元展开。

主线案例：Target 的接口（target.h） 
// target.h
#pragma once
#include <string>

class Target {
public:
    Target(int id, std::string name, int priority);

    void build();
    void rename(const std::string& name);
    bool is_built() const;
    int priority() const;
    void print() const;

private:
    int id_;
    std::string name_;
    int priority_;
    bool built_ = false;
};
接口设计要点

  • 构造函数建立合法状态

  • build / rename 是修改操作

  • is_built / priority / print 是只读操作，全部 const

  • 数据成员私有，表示方式可替换

头文件职责

只放声明和必要的类型定义；实现细节放在 target.cpp，减少编译依赖。

主线案例：Target 的实现（target.cpp） 
// target.cpp
#include "target.h"
#include <iostream>
#include <utility>

Target::Target(int id, std::string name, int priority)
    : id_(id), name_(std::move(name)),
      priority_(priority) {}

void Target::build() { built_ = true; }

void Target::rename(const std::string& name) {
    if (!name.empty()) name_ = name;
}

bool Target::is_built() const { return built_; }
int Target::priority() const { return priority_; }

void Target::print() const {
    std::cout << "[" << id_ << "] " << name_
              << " (p=" << priority_ << ") "
              << (built_ ? "built" : "todo") << "\n";
}
实现要点

  • std::move 避免一次字符串拷贝

  • rename 拒绝空名称，维护不变量

  • 只读函数不修改状态

  • 输出格式集中在一个函数中

[1] main.o (p=2) todo

[2] util.o (p=3) built

课堂任务 2：给 Target 增加状态查询
任务

在上一讲的 Target 类基础上增加：

  1. int id() const：返回目标编号
  2. bool is_high_priority() const：优先级 ≥ 4 返回 true
  3. void raise_priority()：把优先级加 1，最高为 5
  4. void print() const 输出格式： [1] main.o p=2 todo

在 main 中创建 3 个目标，调用 raise_priority() 与 build()，打印全部目标。

验收标准

  • 所有不修改对象的函数都加 const

  • 数据成员保持 private

  • raise_priority() 不能把优先级加到 6

  • 编译无警告：-Wall -Wextra

  • 不使用全局变量

提示

先写接口，再写实现；raise_priority() 可以在类内定义，短小函数更适合放头文件。

课堂任务 2 参考实现（一）：类定义 
#include <iostream>
#include <string>
#include <utility>

class Target {
public:
    Target(int id, std::string name, int priority)
        : id_(id), name_(std::move(name)),
          priority_(priority) {}

    int id() const { return id_; }
    bool is_built() const { return built_; }
    bool is_high_priority() const { return priority_ >= 4; }

    void build() { built_ = true; }

    void raise_priority() {
        if (priority_ < 5) ++priority_;
    }

    void print() const {
        std::cout << "[" << id_ << "] " << name_
                  << " p=" << priority_ << " "
                  << (built_ ? "built" : "todo") << "\n";
    }

private:
    int id_;
    std::string name_;
    int priority_;
    bool built_ = false;
};
关键点

  • 构造函数建立合法状态

  • 查询函数全部 const

  • raise_priority() 把优先级限制在 1..5

  • 数据保持私有，接口足够表达业务

检查

课堂任务 2 参考实现（二）：main 与输出 
#include <vector>
// 假设 Target 定义在 target.h 中（见上一页）

int main() {
    std::vector<Target> tasks;
    tasks.emplace_back(1, "main.o", 2);
    tasks.emplace_back(2, "util.o", 4);

    }
}

运行结果

[1] main.o p=3 todo

[2] util.o p=4 built [3] app p=5 todo

常见错误清单

语法类

  • 类定义末尾漏分号：class A { ... }

  • 类外定义漏 A::

  • 在 const 成员函数中修改成员

  • 把 private 成员当全局变量访问

语义类

  • 忘记初始化数据成员

  • new[] 用 delete 释放

  • 返回局部对象的引用

  • 让 public 函数把内部引用/指针泄露出去

class A {
public:
    int& value() { return value_; }  // 泄露内部状态
private:
    int value_ = 0;
};

A a;
a.value() = 42;   // 绕过所有检查
封装泄露

返回内部数据的非 const 引用，等于把 private 变成 public。只读场景返回 const& 或值。

小结：类是一份契约
对外

  • public 接口：对象能做什么

  • const：哪些操作承诺不修改状态

  • 构造函数：对象创建后即合法

对内

  • private 数据：表示与不变量

  • 成员函数共享一份代码，this 区分对象

  • 成员对象按声明顺序构造、逆序析构

使用

  • 栈对象随作用域，堆对象手动管理

  • 只读用 const&，修改用 &

  • 不泄露内部数据的可变引用

类的价值不在于“把函数放进大括号”，而在于用接口守住不变量，让调用方无法轻易犯错。
