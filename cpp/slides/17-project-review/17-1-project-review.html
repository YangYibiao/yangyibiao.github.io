接口设计：先定契约，再写实现 
class Target {
public:
    virtual ~Target() = default;
    virtual void run() = 0;
    virtual std::string describe() const = 0;
    virtual int id() const = 0;
    virtual int priority() const = 0;
};

class Graph {
public:
    void add(std::unique_ptr<Target> t);
    bool remove(int id);
    Target* find(int id);
    std::size_t size() const;
private:
    std::vector<std::unique_ptr<Target>> targets_;
};

class TargetRepository {
public:
    explicit TargetRepository(std::string path);
    std::vector<std::unique_ptr<Target>> load() const;
    void save(const Graph& list) const;
private:
    std::string path_;
};
设计检查

  • 谁拥有目标？Graph 通过 unique_ptr 独占

  • 外部如何“借用”？返回 Target*，不转移所有权

  • Buildfile 如何描述目标？记录名称、依赖和命令

  • 扩展新目标类型要改哪里？只改工厂/加载逻辑

答辩标准

常见设计错误

类设计

  • 上帝类：一个类做所有事

  • 数据公开，靠注释维持不变量

  • 为了复用而继承

  • 深继承层次

  • 接口返回内部可变引用

资源与并发

  • 裸 new / delete 散落各处

  • 析构函数不释放资源

  • 基类析构非虚

  • 多线程共享数据不加锁

  • 持锁执行耗时操作

  • 用 detach 后访问局部变量

设计错误通常不是“语法不会”，而是“职责不清、所有权不明、边界不定”。

综合案例：从需求到类图

需求片段

系统需要支持多个构建目标；每个目标声明依赖和命令；按依赖图拓扑调度；支持增量构建、并行执行和构建事件。

抽象步骤

  1. 找名词：目标、依赖图、调度器、Buildfile、TargetRepository
  2. 找动词：解析、建图、拓扑排序、增量判断、执行、记录事件
  3. 定职责：谁拥有目标？谁负责拓扑排序？谁负责命令执行与日志？
  4. 定接口：Target::run()、Target::describe()、Graph::add()
  5. 定关系：Scheduler 组合 Graph；Graph 组合 unique_ptr<Target>
Target «interface»
+ run() = 0

+ id() const = 0
+ priority() const = 0
Graph

综合案例：核心代码骨架 
class Target {
public:
    virtual ~Target() = default;
    virtual void run() = 0;
    virtual std::string describe() const = 0;
    virtual int id() const = 0;
    virtual int priority() const = 0;
};

class Graph {
public:
    void add(std::unique_ptr<Target> t) {
        targets_.push_back(std::move(t));
    }

    Target* find(int id) {
        for (auto& t : targets_) {
            if (t->id() == id) return t.get();
        }
        return nullptr;
    }

    void run_all() {
        for (auto& t : targets_) t->run();
    }
private:
    std::vector<std::unique_ptr<Target>> targets_;
};
设计点

  • Target 定义稳定接口

  • Graph 独占拥有目标

  • find 返回借用指针，不转移所有权

  • run_all 通过虚函数动态分派

  • 新增目标类型不需要修改 Graph

注意 Target 还需要 id()；示例省略了构造与具体派生类。完整项目应把接口、实现、测试分开。
复习一：对象生命周期
阶段 发生什么 你要保证
构造 分配空间、初始化成员、执行函数体 对象返回时满足不变量
使用 调用成员函数 不访问已销毁对象
拷贝 拷贝构造 / 赋值 深拷贝资源，处理自赋值
移动 移动构造 / 赋值 源对象置空、noexcept
析构 释放资源 不抛异常、不重复释放

三法则 / 五法则

析构、拷贝构造、拷贝赋值（+ 移动构造、移动赋值）通常要一起考虑。

Rule of Zero

优先让成员（容器、智能指针）管理资源，类本身不写析构/拷贝/移动。

复习二：继承与多态

继承

  • public 继承表达 is-a

  • 构造：基类 → 成员 → 派生

  • 析构：派生 → 成员 → 基类

  • 名字隐藏、对象切片、菱形继承

多态

  • virtual + 指针/引用

  • override 让编译器检查签名

  • 虚析构保证正确释放

  • 抽象类定义接口

  • 少用 dynamic_cast，多用虚函数

高频错误

① 基类析构非虚；② 派生类漏 override / 签名不一致；③ 按值传递导致切片；④ 在构造/析构中调用虚函数。

复习三：资源管理与 STL

资源管理

  • RAII：构造获取、析构释放

  • unique_ptr 独占，shared_ptr 共享，weak_ptr 观察

  • 不要用同一裸指针构造多个 shared_ptr

  • 避免循环引用

  • 容器/字符串/文件流都是 RAII

STL

  • vector 默认；list 频繁中间增删；map 有序查找

  • 算法接迭代器区间 [first, last)

  • 比较器必须严格弱序

  • erase + remove_if；注意迭代器失效

  • Lambda 捕获注意生命周期

共同点

资源管理与 STL 都在回答同一个问题：谁拥有、谁释放、什么时候失效。

复习四：并发

线程

  • std::thread 创建即运行

  • join 等待，detach 放养

  • 参数默认按值复制

  • 线程对象析构前必须 join/detach

同步

  • 数据竞争是未定义行为

  • mutex + lock_guard

  • 临界区尽量小

  • 条件变量必须带谓词

  • 死锁：统一加锁顺序 / scoped_lock

  • 原子操作只适合单变量

并发编程的第一原则：能不共享就不共享；必须共享时，用清晰的同步策略保护它。

易错点清单

语言机制

  • const 成员函数修改成员

  • 拷贝构造参数不写引用

  • 赋值忘记自赋值检查

  • 移动后继续使用源对象

  • 返回局部变量引用

  • new[] 配 delete

  • 基类析构非虚

  • 按值传递导致切片

  • override 签名不一致

工程实践

  • 头文件定义非 inline 函数

  • 模板定义放 .cpp

  • map[] 意外插入

  • 迭代器失效

  • 比较器不满足严格弱序

  • 条件变量不用谓词

  • 持锁执行耗时操作

  • detach 后访问局部变量

  • 异常路径资源泄漏

考前逐条自查：能说出“为什么错、怎么改、如何避免”，比背结论更有效。

    ~Base() { f(); }

参考答案要点

模拟题 1

  • 虚析构：通过基类指针删除派生对象时，保证派生类析构执行

  • 拷贝构造：初始化新对象；拷贝赋值：覆盖已有对象

  • 三法则：三者共同定义资源所有权

  • unique_ptr 独占、零开销；shared_ptr 共享、引用计数

  • 数据竞争：并发访问共享数据且至少一个写；mutex 保护临界区，atomic 保护单变量，条件变量等待状态

模拟题 2

  • 输出 BB（构造 Base 时调用 Base::f，析构 Base 时也调用 Base::f）

  • 构造/析构期间不进行派生类分派

  • 把析构改为 virtual 仍输出 BB；虚析构解决的是“删除时调用派生析构”，不改变基类构造/析构中的调用

  • 潜在问题：在构造/析构中调用虚函数；基类析构非虚（若通过基类指针删除）

模拟题 3 的答案不唯一，重点看接口、所有权、扩展性与解释是否自洽。
