Defects reported by three testing techniques for code-coverage profilers. The list covers 112 paper-reported defects; 14 no longer reproduce on the latest toolchain and 2 still reproduce despite being marked fixed in the paper. Two follow-up reports were filed in November 2026.

Status. Fixed and disappeared IDs are struck through. “Disappeared” means the triggering program no longer exposes the defect on the latest toolchain; in several cases the issue appears to have been fixed together with another defect. “Regression” means the paper marked the bug Fixed but it still reproduces on trunk. Other rows keep the status reported in the paper; no new change was observed in the latest-version recheck.

Bug numbering. All LLVM IDs now link to GitHub issues (github.com/llvm/llvm-project/issues/<id>). The 2019 Bugzilla IDs were mapped to their migrated GitHub issues by title search; when the paper ID differs, the cell shows paper-ID → #github-ID. GCC IDs link to GCC Bugzilla.

Tracker status. For LLVM, this is the current GitHub state (open/closed, with close date). For gcov, it is the Bugzilla status recorded in the paper; GCC Bugzilla blocks automated retrieval, so the linked page has the current value.

Reported date. Exact dates come from GitHub or Bugzilla where available. For GCC Bugzilla rows, the table shows the paper’s reporting window; the linked Bugzilla page has the exact timestamp.

Newly re-reported (Nov 2026). Developers asked for new reports for the two reproducible regressions; they were filed as GCC Bugzilla #128557 and #128558 and are listed at the end of this page.
