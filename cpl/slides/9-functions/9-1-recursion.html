函数调用栈 · 概念

函数不执行的时候是什么? 编译后它只是代码区里静静躺着的一段指令——像书架上的菜谱, 不做事也不占台面; 一被调用, 系统才为这一次调用在栈上放一张便签。同一张菜谱能反复做菜——同一个函数每次调用都是独立的一次:

先想一个问题: 函数返回之后, 它里面的局部变量去了哪里? 下次再调用, 为什么又是全新的?

  • 每次函数调用, 系统在调用栈 (call stack) 上放一张 "便签"——术语叫栈帧 (stack frame): 记下返回地址、参数、局部变量

  • 返回地址: 函数结束后, 回到调用处继续执行的下一行

  • 函数返回时揭掉这张便签——局部变量 "出了函数就没了", 就是这个原因

  • 栈是后进先出: 最后调用的函数最先返回——像一摞便签, 后放的压在最上面, 只能先揭最上面那张

函数调用栈 · 便签上放了什么 
/* primes.c 函数版: 两层调用链 */
#include <stdio.h>
int is_prime(int n) {
  if (n <= 1) return 0;
  for (int d = 2; d <= n / d; d++) {
    if (n % d == 0) return 0;
  }
  return 1;
}
int count_primes(int max) {
  int count = 0;
  for (int i = 2; i <= max; i++) {
    if (is_prime(i)) count++;
  }
  return count;
}
int main(void) {
  printf("%d\n", count_primes(10));
  return 0;
}
primes.c 函数版: main → count_primes → is_prime 两层调用, 栈上三张便签

  • is_prime 返回时, 栈顶的便签被撕掉: 局部变量 d 随之消失, 控制权按 "返回地址" 回到 count_primes

  • count_primes 的循环一次次调用 is_prime, 每次都放一张全新的便签——所以每次的局部变量都是新的

  • 数组作参数时, 便签上记的不是整个数组, 而是数组的开头位置——函数顺着位置改到原数组; 普通参数记的是值的副本——这就是 "数组是例外" 的原因

标识符的作用域 
int x = 0;            /* 文件作用域 */
void f(void)
{
  int x = 1;        /* 块作用域, 屏蔽全局 x */
  printf("%d", x);  /* 打印 1 */
}

作用域: 标识符可以被使用的那段代码范围

  • 块作用域: 函数体内 {} 覆盖的范围——局部变量、形式参数

  • 文件作用域: 从定义位置到文件末尾——全局变量

  • 内层屏蔽外层: 内层同名变量会遮蔽外层的

局部变量: 定义在函数内, 出了函数就不可见

  • 全局变量: 定义在函数外, 整个文件可见; 少用为妙 (谁都可能改它)

变量的生命期

  • 动态变量(默认): 函数被调用时诞生, 函数返回时消亡

  • 动态变量与递归: 递归的每一层调用都是一次独立的函数调用——各层的参数和局部变量随层生、随层亡, 互不干扰 (上一页"每层一套自己变量"的底层原因就在这里)

  • 静态变量(static): 与程序同生共死, 函数返回后保留原值

void f(void)
{
  static int count = 0;  /* 只初始化一次 */
  count++;
  printf("第 %d 次调用\n", count);
}

  • static 局部变量 = 带记忆的局部变量 (下次调用接着用上次的值)

演示: 局部变量的"垃圾值"
代码
void f(void) {
    int i;                    /* 没有初始化 */
    printf("i = %d\n", i);
}
int main(void) { f(); return 0; }

一次运行的结果 (每次可能不同!):

i = 32764
要点

  • 动态局部变量诞生时不会自动清零——里面是内存里残留的"垃圾值"

  • 每次运行、每台机器都可能不同; 调试器里恰好是 0 只是假象

  • 教训: 局部变量必须初始化后再使用; 编译加 -Wall 有时能提示 "used uninitialized"

  • 后面讲递归时也一样: 每层调用的局部变量各自独立, 忘初始化同样读到垃圾值

递归是什么

递归: 函数直接或间接地自己调用自己——有些问题的定义本身就是递归的: 阶乘、汉诺塔、目录遍历……

代码
/* 阶乘: n! = n × (n-1)! */
long long f(long long n)
{
  if (n == 0) {            /* 基准: 0! = 1, 唯一的奠基 */
    return 1;
  }
  return n * f(n - 1);     /* 递归: 1! 由 0! 归纳出来 */
}
要点

  • 两个要素: 基准情形 (最简单, 直接给答案) + 递归情形 (缩小后再调用自己)

  • 信任递归: 假设 n-1 层的答案是对的, 用它构造 n 的答案——不要在脑中展开所有层

  • 递归三问: 最小问题? 怎么缩小? 怎么构造当前答案?

  • 为什么能自己调用自己? 函数名只是代码的入口——每次调用都开一张新便签、配一套新参数, 互不干扰

递归 = 归纳法的计算版本: 基准 = 奠基, 递归 = 归纳, 信任 = 归纳假设

递归执行过程: 压栈与返回

fact(3) 的跟踪——递推下去, 再回归上来:

  • 每一层调用压一张便签 (昨天的栈), 回归时逐层弹栈结算——递归就是便签一层层叠高、再一层层揭掉

  • 每层调用有自己的一套局部变量和参数, 各层互不干扰 (作用域与生命期见上一讲)

  • 递归深度 = 压栈层数; 递归过深 → 栈溢出

Fibonacci 数列
代码
#include <stdio.h>
long long fib(long long n)
{
  if (n == 0) {              /* 奠基之一: F(0) = 0 */
    return 0;
  }
  if (n == 1) {              /* 奠基之二: F(1) = 1 */
    return 1;
  }
  return fib(n - 1) + fib(n - 2);
}
int main(void)
{
  printf("fib(10) = %lld\n", fib(10));
  return 0;
}

样例输出: fib(10) = 55

要点

  • 两个奠基: 递推式需要前两项, 所以基准情形有两个、返回不同值 (对比阶乘: 只靠 0! 一个奠基就够)

  • F(n) = F(n-1) + F(n-2): 一次调用分成两个分支——递归展开成一棵二叉树, 深度 n、最多 2ⁿ 个结点

  • 重复计算: fib(5) 会把 fib(3) 算 2 遍、fib(2) 算 3 遍——朴素递归的代价; 优化办法 (记忆化/动态规划) 课下可以了解

Hanoi 塔 · 任务与规则

传说: 印度教寺庙里有 3 根柱子、64 个金盘, 僧侣昼夜不停地移动; 传说 64 个盘移完之日就是世界末日——放心, 一共要 2⁶⁴ − 1 步, 约 5849 亿年

初始 (n = 3)
目标

盘子编号: 最小的叫 盘 1 (叠在最上面), 往下依次是 盘 2、盘 3……, 最大的叫 盘 n (最下面; 后面代码输出的就是这些编号)

目标: 把 n 个盘子从 A 柱全部移到 C 柱, 结束时仍然上小下大 (和初始状态一样)

规则:

  • 每次只能移动一个盘子 (某根柱最上面的)

  • 大盘不能压在小盘上

  • 可以借 B 柱暂存

任务: 给定任意 n, 设计算法输出全部移动步骤 (每一步: 哪个盘、从哪柱到哪柱)

Hanoi 塔 
/* hanoi.c: A = 起始柱, B = 辅助柱, C = 目标柱;
   n = 本次要移的盘数 (最大盘编号) */
#include <stdio.h>

void Hanoi(int n, char A, char B, char C)
{
  if (n == 1) {
    /* 基准: 只剩一个盘 */
    printf("盘 %d: %c -> %c\n", n, A, C);
  } else {
    /* 上面 n-1 个: A -> B (借 C) */
    Hanoi(n - 1, A, C, B);
    /* 最大盘: A -> C */
    printf("盘 %d: %c -> %c\n", n, A, C);
    /* 上面 n-1 个: B -> C (借 A) */
    Hanoi(n - 1, B, A, C);
  }
}

int main(void)
{
  /* 3 个盘的完整移法 */
  Hanoi(3, 'A', 'B', 'C');
  return 0;
}
① n-1 个: A → B (虚线)    ② 盘 n: A → C (实线)    ③ n-1 个: B → C (虚线)

刚才的动画 (3 个盘、7 步) 正是来自下面的分解 (A 起始、B 辅助、C 目标):

  • ① 先把上面 n-1 个 A → B (借 C)——同类问题小 1

  • ② 把最大盘 n 直接 A → C——一步完成

  • ③ 再把那 n-1 个 B → C (借 A)

①③ 交给递归; n = 1 直接 A → C (基准情形)

常见错误

  • 缺少基准情形: 递归永不终止 (如忘了 n==0 的判断)

  • 问题没有缩小: 每次调用与上次规模相同 (如 f(n) 里调用 f(n))

写递归的两步检查: ① 基准情形对吗? ② 每次调用规模在变小吗?

演示: 没有基准情形的栈溢出
代码
/* 不规范: 少了基准情形 */
long long fact(int n)
{
  return n * fact(n - 1);
}

int main(void)
{
  printf("%lld\n", fact(5));
  return 0;
}

运行结果: 一阵呼啸之后——

Segmentation fault (core dumped)

⚡ 在 VS Code 中打开 stack-overflow.c (直接编译运行, 看它崩溃)
要点

  • 每一层调用压一张便签; 没有基准情形, 便签就无限叠高——谁也不返回, 谁也腾不出空间

  • 栈的空间是有限的 (默认几 MB): 用尽即 栈溢出 (stack overflow), 程序直接崩溃

  • 即使有基准情形, 极大的递归也会爆: 递归深度以"层"计, 大输入要留意 (如对 10 万个元素的数组递归求最大值)

  • 应对: 递归三问缺一不可; 有些递归能改写成循环——循环不占栈, 深了也不怕 (这是"尾递归优化"的朴素版理解)

课堂编码 · 参考实现
参考实现 1: 递归求幂
int power(int x, int n)
{
  /* 基准 x^0=1; 递归 x × x^(n-1) */
  return n == 0 ? 1 : x * power(x, n - 1);
}

  • 参数即状态: 底数 x 全程不变, 指数 n 逐层减 1——两个量都要进参数, 缺一不可

  • 基准情形: n == 0 → 1; 递归情形把问题缩小成 x^(n-1)

参考实现 2: 递归求和
int sum(int n)
{
  /* 基准 0; 递归 n + sum(n-1) */
  return n == 0 ? 0 : n + sum(n - 1);
}

  • 参数即状态: 只带 n——"加到几为止"就是子问题的全部状态

  • 基准情形: n == 0 → 0; 递归情形: sum(n) = n + sum(n-1)

参考实现 3: 递归打印整数
void print(int n)
{
  if (n / 10 == 0) {
    /* 基准: 一位数直接打印 */
    printf("%d", n);
  } else {
    /* 先递归打印前面几位 */
    print(n / 10);
    /* 回来再打印末位 —— 顺序是本题关键 */
    printf(" %d", n % 10);
  }
}

  • 参数即状态: 只带 n; 顺序是本题关键——先递归打印 n/10, 回来再打印末位 n%10, 得到正序

  • 基准情形: 一位数 (n / 10 == 0) 直接打印

#include <stdio.h>

void print_bin(int n)
{
    if (n < 2) {
        printf("%d", n);
        return;
    }
    print_bin(n / 2);
    printf("%d", n % 2);
}

{
    print_bin(10);
    printf("\n");
    print_bin(0);
    printf("\n");
    print_bin(13);
    printf("\n");
    return 0;
}

案例 4: 递归求最大值
int max_rec(int a[], int n)
{
  int rest;
  if (n == 1) {                    /* 基准情形 */
    return a[0];
  }
  rest = max_rec(a, n - 1);        /* 递归: 前 n-1 个的最大值 */
  return a[n - 1] > rest ? a[n - 1] : rest;
}

  • 递归情形里先信任 max_rec(a, n-1) 是对的, 再拿 a[n-1] 和它比——这就是"信任递归"

案例 5: 判断回文
int is_pal(char s[], int l, int r)
{
  if (l >= r) {                    /* 基准: 0 或 1 个字符 */
    return 1;
  }
  return s[l] == s[r] && is_pal(s, l + 1, r - 1);
}

  • 参数即状态: l、r 刻画当前子串——不复制字符串, 只移动两个下标

  • 定义即代码: 把"首尾相等且中间是回文"逐字翻译出来, 就是函数体

课堂案例: 二分查找 · 参考实现 
int bin_search(int a[], int low, int high, int key)
{
  int mid;
  if (low > high) {                /* 基准: 没找到 */
    return -1;
  }
  mid = (low + high) / 2;
  if (a[mid] == key) {
    return mid;
  }
  if (a[mid] > key) {
    return bin_search(a, low, mid - 1, key);
  }
  return bin_search(a, mid + 1, high, key);
}

  • 参数即状态: 递归函数的参数要能完整描述"当前子问题"——low、high 刻画查找区间, key 与 a 全程不变

  • 每次调用区间必然缩小——这保证递归一定终止; 下一页分治法正是这个思想的放大版

案例 7: 组合数
long comb(int m, int n)
{
  if (n == 0 || n == m) {          /* 基准情形 */
    return 1;
  }
  return comb(m - 1, n - 1) + comb(m - 1, n);
}

  • 同一行里两个递归调用——先展开一层看: "选中第 m 个"与"不选第 m 个"两类, 加起来

案例 8: 爬楼梯
int climb(int n)
{
  if (n <= 1) {                    /* 基准情形 */
    return 1;
  }
  return climb(n - 1) + climb(n - 2);
}

  • 生活问题→递归定义: 走到第 n 级的方法数 = 走到 n-1 的方法数 + 走到 n-2 的方法数

分治法

分治法 (divide and conquer): 把大问题拆成几个同类的小问题, 分别解决, 再合并结果

  • 三步: 分 (拆) → 治 (解决小问题) → 合 (拼起来)

  • 生活例子: 整理一摞试卷——先按分数段分堆, 每堆再各自整理

  • 排序中的分治 (快速排序): 选一个基准, 把数组划分成"小的在左、大的在右"两段, 再对两段各自递归——不需要合并 (划分完位置就对了); 过程见下一页

  • ("分成两半各自排好再合并"是另一种排序——归并排序, 课下可以了解)

递归常常是分治法的自然结果——快速排序正是如此

分治图示: 快速排序

  • ① 划分: 选基准 5, 小的放左、大的放右——5 的位置就此一次到位

  • ② 治: 左段 [2, 1, 3] 和右段 [9, 8] 各自递归——同样先划分、再递归

  • ③ 合: 什么都不用做——每次划分都把基准放到最终位置, 递归结束时整个数组就有序了

递归排序: 快速排序

用递归做排序: 选一个基准, 小的放左、大的放右, 再对左右递归

void quicksort(int a[], int low, int high)
{
  int middle;

  if (low >= high) {          /* 基准情形: 只剩 0 或 1 个元素 */
    return;
  }
  middle = split(a, low, high);       /* 划分: 小的在左, 大的在右 */
  quicksort(a, low, middle - 1);      /* 递归排左半 */
  quicksort(a, middle + 1, high);     /* 递归排右半 */
}

  • 平均 O(n log n), 比之前三种排序的 O(n^2) 快得多

  • split 是划分函数, 下一页展开

快速排序: 划分函数 split 
int split(int a[], int low, int high)
{
  int part_element = a[low];

  for (;;) {
    while (low < high && part_element <= a[high]) {
      high--;
    }
    if (low >= high) {
      break;
    }
    a[low++] = a[high];

    while (low < high && a[low] <= part_element) {
      low++;
    }
    if (low >= high) {
      break;
    }
    a[high--] = a[low];
  }

  a[high] = part_element;
  return high;
}

split: 以 a[low] 为基准, 把小元素换到左边、大的换到右边, 返回基准的最终下标
