本讲目标

能够判断一个类是否需要自定义拷贝/赋值，并写出正确的深拷贝与赋值运算符。

对象复制的三个场景

1. 用已有对象初始化新对象

Target a(1, "main.o", 2);
Target b = a;      // 拷贝构造
Target c(a);       // 拷贝构造

2. 按值传参

void print_target(Target t);  // 创建形参副本
print_target(a);

3. 按值返回

Target make_target() {
    Target t(1, "临时", 1);
    return t;     // 可能调用拷贝/移动构造
}
注意区分
Target b = a;   // 初始化：拷贝构造
b = a;        // 赋值：operator=

虽然都写作 =，但语义完全不同：

  • 初始化：对象从无到有

  • 赋值：对象已经存在，用新值覆盖旧值

记忆

看等号左边是不是新定义的变量。是，则初始化；不是，则赋值。

拷贝构造函数 
class Target {
public:
    Target(int id, std::string name, int priority)
        : id_(id), name_(std::move(name)),
          priority_(priority) {}

    // 拷贝构造函数
    Target(const Target& other)
        : id_(other.id_), name_(other.name_),
          priority_(other.priority_), built_(other.built_) {}

private:
    int id_;
    std::string name_;
    int priority_;
    bool built_ = false;
};
识别

  • 参数是本类对象的引用：const Target&

  • 通常加 const，因为拷贝不应修改源对象

  • 没有返回值

  • 一个类只能有一个拷贝构造函数

为什么必须传引用

如果写成 Target(Target other)，传参本身又要拷贝，会无限递归。

默认拷贝构造：逐成员拷贝 
class Target {
    int id_;
    std::string name_;
    int priority_;
    bool built_ = false;
    // 没有自定义拷贝构造
};

Target a(1, "main.o", 2);
Target b = a;

编译器生成的拷贝构造等价于：

Target(const Target& other)
    : id_(other.id_), name_(other.name_),
      priority_(other.priority_), built_(other.built_) {}
逐成员含义

  • 基本类型：复制值

  • 类类型成员：调用其拷贝构造

  • 指针成员：只复制指针值（浅拷贝）

  • 数组：逐元素复制（数组成员不能直接赋值）

结论

如果所有成员都能安全地“按值复制”，默认拷贝构造就够用。Target 的 std::string 会自己深拷贝，所以安全。

浅拷贝：两个对象共用一块资源 
class String {
public:
    explicit String(const char* s)
        : len_(std::strlen(s)),
          data_(new char[len_ + 1]) {
        std::strcpy(data_, s);
    }
    ~String() { delete[] data_; }
private:
    std::size_t len_;
    char* data_;
};

String s1("abcd");
String s2 = s1;   // 默认拷贝：只复制指针
浅拷贝后的内存
s1len_=4, data_=0x1000
s2len_=4, data_=0x1000
0x1000'a' 'b' 'c' 'd' '\0' ← 两个对象共享
后果

① 一方修改会影响另一方；② 两个析构函数各 delete[] 一次 → 双重释放；③ 一方先销毁，另一方变成悬空指针。

深拷贝：每个对象拥有自己的资源 
class String {
public:
    String(const String& other)
        : len_(other.len_),
          data_(new char[other.len_ + 1]) {
        std::strcpy(data_, other.data_);
    }
    // ...
private:
    std::size_t len_;
    char* data_;
};
深拷贝后的内存
s1len_=4, data_=0x1000
s2len_=4, data_=0x2000
0x1000'a' 'b' 'c' 'd' '\0'
0x2000'a' 'b' 'c' 'd' '\0' ← 新分配
所有权

每个 String 对象拥有自己的一块字符数组，析构时各自释放，互不干扰。

拷贝构造中的成员对象 
class A {
public:
    A() { std::cout << "A() "; }
    A(const A&) { std::cout << "A(const A&) "; }
};

class B {
public:
    B() { std::cout << "B() "; }

    B(const B& b) : a_(b.a_) {   // 显式拷贝成员
        std::cout << "B(const B&) ";
    }
private:
    A a_;
};
关键规则

  • 自定义拷贝构造不会自动拷贝成员对象

  • 默认调用成员对象的默认构造函数

  • 要拷贝成员对象，必须在初始化列表中显式调用其拷贝构造

常见错误 B(const B& b) { a_ = b.a_; }：a_ 先被默认构造，再被赋值；如果 A 不可默认构造，直接编译失败。
拷贝赋值：对象已经存在 
class Target {
public:
    Target& operator=(const Target& other) {
        if (this == &other) return *this;  // 自赋值

        id_ = other.id_;
        name_ = other.name_;
        priority_ = other.priority_;
        built_ = other.built_;
        return *this;
    }
    // ...
};
Target a(1, "A", 1);
Target b(2, "B", 2);
b = a;      // 调用 operator=
默认赋值

编译器生成逐成员赋值：

  • 基本类型：赋值

  • 类类型成员：调用其 operator=

  • 指针成员：只复制指针值（浅拷贝）

返回引用

返回 *this 的引用，支持 a = b = c 这样的连续赋值。

自定义赋值：四个关键动作 
String& operator=(const String& other) {
    if (this == &other) {       // 1. 自赋值检查
        return *this;
    }

    char* new_data = new char[other.len_ + 1];  // 2. 先分配
    std::strcpy(new_data, other.data_);

    delete[] data_;             // 3. 再释放旧资源
    data_ = new_data;
    len_ = other.len_;

    return *this;               // 4. 返回自身
}
为什么这个顺序

  • 先 new：如果分配失败抛出异常，旧对象仍然完好

  • 再 delete：避免释放后拷贝源数据（源可能和自己是同一块）

  • 先拷贝到临时指针：防止 new 成功后 strcpy 失败导致半成品

异常安全

这个顺序提供强异常安全保证：赋值失败时，对象保持原值。

自赋值：a = a 为什么危险？

没有自赋值检查

String& operator=(const String& other) {
    delete[] data_;                 // 释放自己的数据
    data_ = new char[other.len_ + 1];
    std::strcpy(data_, other.data_); // other 就是自己！
    // data_ 已被释放，other.data_ 悬空
}
两种处理方式
  1. 地址检查：if (this == &other) return *this;
  2. 拷贝并交换：先复制实参，再交换，天然处理自赋值
现实场景

自赋值不一定写成 a = a，也可能是 v[i] = v[j] 且 i == j，或通过引用间接发生。

更稳健的写法：拷贝并交换 
class String {
public:
    String& operator=(String other) {  // 按值：先复制
        swap(other);
        return *this;
    }

    void swap(String& other) noexcept {
        std::swap(len_, other.len_);
        std::swap(data_, other.data_);
    }
private:
    std::size_t len_ = 0;
    char* data_ = nullptr;
};
优点

  • 自赋值安全：交换自己不会出问题

  • 异常安全：复制在进入函数前完成

  • 代码短，swap 可复用

  • 移动语义章节可以直接复用

前提 swap 必须不抛出异常（noexcept），否则异常安全保证会被破坏。
三法则

如果你需要自定义析构函数、拷贝构造函数或拷贝赋值运算符中的任何一个，通常三个都需要。

析构函数

释放对象拥有的资源。

拷贝构造

复制资源，而不是复制指针。

拷贝赋值

先释放旧资源，再复制新资源。

为什么

三者共同定义“对象如何拥有资源”。只写其中一个，另外两个的默认行为（浅拷贝、浅赋值）就会破坏所有权模型。

C++11 引入移动语义后，三法则扩展为五法则：再加上移动构造与移动赋值。下一单元展开。

不需要拷贝的类：禁止拷贝 
class FileHandle {
public:
    explicit FileHandle(const char* path)
        : fp_(std::fopen(path, "r")) {}

    ~FileHandle() { if (fp_) std::fclose(fp_); }

    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;

private:
    std::FILE* fp_;
};
语义

文件句柄、锁、网络连接等资源通常不能被复制：

  • 复制后两个对象都以为自己拥有资源

  • 析构时重复关闭/释放

= delete 让错误在编译期暴露。

C++11 之前

把拷贝构造/赋值声明为 private 且不实现，也能达到禁止拷贝的效果；= delete 更清晰。

传值、传引用与返回值优化

按值传参：一次拷贝

void print_target(Target t);   // 拷贝构造
print_target(a);

传常量引用：零拷贝

void print_target(const Target& t);
print_target(a);

返回对象：通常零拷贝

Target make_target() {
    return Target(1, "临时", 1);
}

Target t = make_target();
RVO / NRVO

编译器可以把返回值直接构造在调用方预留的空间中，省略拷贝/移动。这是允许的优化，C++17 起部分场景是强制的。

不要做的优化

不要为了“减少拷贝”而返回局部对象的引用或指针——对象已经销毁，结果是悬空引用。让编译器做 RVO。

主线案例：Target 需要自定义拷贝吗？ 
class Target {
public:
    Target(int id, std::string name, int priority)
        : id_(id), name_(std::move(name)), priority_(priority) {}

    void rename(const std::string& name) { name_ = name; }

private:
    int id_;
    std::string name_;
    int priority_;
    bool built_ = false;
};

Target a(1, "main.o", 2);
Target b = a;      // 默认拷贝：安全
b.rename("util.o"); // b 的 name_ 独立
判断依据

Target 的成员：

  • int、bool：值复制

  • std::string：自己的拷贝构造做深拷贝

因此默认拷贝构造和默认赋值已经正确，不需要三法则。

原则

只有当类直接持有裸资源（new 出来的指针、文件句柄、锁）时，才需要自己管理拷贝。优先让成员替你管理资源。

提示

先写析构、拷贝构造、拷贝赋值三个函数；再思考赋值时“先分配、后释放”的顺序。

任务 4 参考实现 
#include <cstddef>
#include <cstring>
#include <iostream>
#include <utility>

class String {
public:
    explicit String(const char* s = "")
        : len_(std::strlen(s)),
          data_(new char[len_ + 1]) {
        std::strcpy(data_, s);
    }

    String(const String& other)
        : len_(other.len_),
          data_(new char[other.len_ + 1]) {
        std::strcpy(data_, other.data_);
    }

    String& operator=(const String& other) {
        if (this == &other) return *this;
        char* new_data = new char[other.len_ + 1];
        std::strcpy(new_data, other.data_);
        delete[] data_;
        data_ = new_data;
        len_ = other.len_;
        return *this;
    }

    ~String() { delete[] data_; }

    const char* c_str() const { return data_; }
    std::size_t size() const { return len_; }

private:
    std::size_t len_;
    char* data_;
};

要点

  • 拷贝构造分配新数组

  • 赋值先分配后释放，保证异常安全

  • 自赋值检查避免释放后使用

  • 三法则齐全

常见陷阱

拷贝构造

  • 参数不写引用 → 无限递归

  • 忘记拷贝成员对象 → 成员被默认构造

  • 只复制指针 → 浅拷贝

  • 拷贝构造中修改源对象

拷贝赋值

  • 忘记自赋值检查

  • 先 delete 再读源数据 → 悬空指针

  • 返回 void → 无法连续赋值

  • 只复制指针 → 双重释放

  • 异常发生后对象处于半成品状态

判断口诀

“有资源，想三件事：谁释放、怎么复制、怎么赋值。”如果资源已经由成员（如 std::string、std::vector）管理，就让成员去做。

小结：复制的是值，管理的是所有权
拷贝构造

用已有对象初始化新对象；默认逐成员拷贝；有裸资源时要深拷贝。

拷贝赋值

覆盖已存在对象；处理自赋值、异常安全、返回 *this；可用拷贝并交换。

三法则

析构、拷贝构造、拷贝赋值共同定义资源所有权；不需要就 = delete。

拷贝的难点不在“复制数据”，而在谁拥有资源、谁负责释放。想清楚所有权，代码自然正确。
