# 课堂签到(二维码在哪, 就在哪签到)

## 使用流程

1. **课前准备(每学期一次)**:改 `config.js` 里的 `secret`(防猜到码的规律);`zones` 是"手动输码模式"的兜底区域, 一般不用动。
2. **上课时**:教师电脑打开 `teacher.html` 全屏投影:
   - 点 **"获取我的位置"**(教室电脑没有 GPS 的话, 在下方面板手动填经纬度);
   - 屏幕上的二维码会**自动带上教师当前的位置**和当次签到码, 每 60 秒更换;
   - 大号 6 位码保留在屏幕上, 供不能扫码的同学手动输入。
3. **学生**:手机扫二维码 → 学号 → 允许定位 → 在**二维码所在位置附近**(默认半径 400 米, 取定位精度自动调整)自动判定 → 绿色"签到成功"及凭证。
4. **收尾**:学生出示成功页/截图接龙; 教师端"凭证核验"可抽查真伪。

## 机制

- 签到码 = SHA-256(secret + 分钟数) 前 8 位十六进制取模 → 每 60 秒换一次。
- 二维码 URL 携带 `slot + 码 + 教师当前位置 + 半径`, 学生页按二维码里的坐标做距离判定 —— **换教室/机房不用改任何配置, 二维码在哪就在哪签到**。
- 凭证 = SHA-256(学号 + 分钟槽) 前 10 位, 教师端可离线核验(±3 分钟)。
- 手动输码模式(二维码带不上位置时)回退到 config.js 的 zones 固定区域。

## 安全边界(重要)

纯静态方案, 不是严格防作弊:定位可被模拟(开发者选项), 码可由在场同学转发, 前端逻辑可被查看。对大一课程考勤够用; 若出现代签, 升级方向是服务端校验(如部署到校内 OJ 服务器)。页面必须 https 访问(GitHub Pages 天然满足), 否则浏览器加密接口不可用。

## 签到数据收集(必做)
签到成功页会把"学号 + 凭证 + 时间"复制到剪贴板, 并打开收集表让学生提交:
1. 建一个问卷(腾讯问卷/问卷星/金数据, 一题"签到信息"即可);
2. 把链接填进 `config.js` 的 `formUrl`;
3. 课后在问卷后台导出 Excel —— 这就是当次课的签到名单。

## 文件

- `config.js` — 密钥与兜底区域(每学期改一次)
- `index.html` — 学生签到页
- `teacher.html` — 教师端:大屏码 + 带位置的二维码 + 凭证核验
